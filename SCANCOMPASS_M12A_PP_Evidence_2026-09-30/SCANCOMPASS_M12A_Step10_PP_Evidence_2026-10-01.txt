PURPOSE
Add a second network-security layer below the scanner application: a host nftables policy
that limits forwarded scanner-container traffic to the destination classes and ports the
scanner is supposed to reach. The host policy is generated from the same committed address
authority used by the application so it cannot quietly drift into a second hand-maintained list.

Docker's container-visible resolver was 127.0.0.11.

Measured host-forward behavior showed:
- normal scanner HTTPS crossed the host forward path;

- direct TCP/53 to a public resolver was blocked by the scanner port policy.

Therefore no host DNS exception was required.

FIRST-PASS SECURITY DEFECTS FOUND BY REVIEW
The first M12A-10 implementation passed its own acceptance but was rejected on review.

Five issues were found:
1. Longest-prefix IANA exceptions were swallowed by broad deny prefixes.
2. An outbound established/related conntrack rule could preserve unauthorized pre-existing flows.
3. E2 proved only a TCP/53 handshake, not a real DNS-over-TCP exchange.
4. Docker-shipped worker-bundle identity had not been re-proven after worker-reachable source changed.
5. Embedded-IPv4 documentation disagreed with executable source.

LONGEST-PREFIX CORRECTION
The generator now computes the actual denied address set.

It:
- builds boundaries from relevant registry/structural/metadata prefixes;
- divides address space into uniform segments;
- asks classifyAddress() itself to classify representative points;
- fails generation if a supposedly uniform segment disagrees;
- merges adjacent denied segments;
- emits CIDRs or nftables interval ranges.

Example:
- 192.0.0.0–192.0.0.8 denied
- 192.0.0.9 allowed
- 192.0.0.10 allowed
- 192.0.0.11–192.0.0.255 denied

Nested globally reachable IPv6 exceptions under broader non-reachable blocks are also preserved.

PORT / CONNTRACK CORRECTION
Final outbound scanner chains now:
1. deny prohibited destinations;
2. allow TCP 80/443;
3. drop everything else.

The unrestricted outbound `ct state established,related accept` rule was removed.

A live E24 test held a public TCP/4242 flow open while the policy was activated:
- old rule shape: same connection continued after activation;
- corrected rule shape: post-activation traffic stopped and the deny-port counter advanced.

DNS-OVER-TCP CORRECTION
A dedicated acceptance probe sends a real length-prefixed RFC 1035 DNS query and verifies:
- transaction ID echo;
- QR bit;
- RCODE;
- answer count;
- parsed answer records.

Docker's 127.0.0.11 resolver successfully answered while scanner-forward firewall counters stayed unchanged.

ADDRESS / IPv6 MODEL
Prefix-expressible application deny classes are represented at the host layer.

Parser-only classes remain application-layer:
- DENY_UNPARSEABLE
- DENY_UNCERTAIN
- DENY_SCOPED_ADDRESS

IPv6 remains fail-closed around the 2000::/3 global-unicast allocation.

Correct embedded-IPv4 source truth:
- IPv4-mapped addresses adopt the inner IPv4 classification in application code;
- the host blocks that carrier wholesale, so this is a deliberate stricter host rule;
- NAT64, 6to4, Teredo and IPv4-compatible transition forms are already denied by application code.

IPv6 was proven unavailable on scanner_egress in the disposable environment rather than silently skipped.

REBOOT DURABILITY
The systemd design itself required iteration.

Two failed designs were preserved as evidence:
- an over-length placeholder interface name caused nft validation failure;
- PartOf/ExecStop coupling caused the firewall table to be removed shortly after installation.

The final unit:
- uses a valid placeholder;
- validates interface-name length;
- waits boundedly for the bridge;
- uses After/Wants for Docker;
- has no PartOf;
- has no Requires coupling;
- has no ExecStop removal path.

The policy returned after reboot without manual repair and the corrected acceptance matrix passed again.

ROLLBACK

- leave Docker firewall rules unchanged;
- be idempotent.

blocked -> connected after removal -> blocked after reapply.
