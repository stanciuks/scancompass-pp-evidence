Project: Scancompass
Milestone: M12A — Scanner worker isolation

STEP: M12A-0 — Source audit and isolation-boundary investigation
STATUS: COMPLETE (read-only design/audit step)

PURPOSE
Establish the real current architecture before extracting scanner execution into a separate
worker process. The step deliberately treated repository source as authoritative for current
behaviour and recorded documentation drift rather than silently trusting old prose.

WHAT THIS STEP ESTABLISHED
- M12A would separate hostile-network parsing/scanning from the web application process.
- The web tier would remain responsible for admission, denylist/cooldown/duplicate suppression,
  scoring, report composition, persistence, cache and later account/domain-authorisation work.
- The worker would receive only the narrow information necessary to execute a free scan.
- No queue, persistent job store, automatic retry or resumption would be introduced.
- Scanner identity, cancellation, runtime resources, networking and egress would each need an
  explicit trust-boundary design rather than being assumed to follow automatically from
  "putting it in another container".
- Documentation drift was tracked separately so historical reasoning would not be rewritten.

EVIDENCE / REVIEW CHARACTER
This step was intentionally read-only:
- no source files created or changed;
- no production contact;
- no environment/secret reads;
- no Docker/firewall/network changes;
- no tag movement.

assumptions were identified, and the implementation was split into independently verifiable steps.
