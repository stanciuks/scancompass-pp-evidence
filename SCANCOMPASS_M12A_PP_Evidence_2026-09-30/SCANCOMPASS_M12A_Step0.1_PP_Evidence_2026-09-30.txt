Project: Scancompass
Milestone: M12A — Scanner worker isolation

STEP: M12A-0.1 — Corrected worker-isolation design
STATUS: COMPLETE (read-only design revision)

PURPOSE
Turn the source audit into a concrete implementation design and resolve the major trust-boundary
questions before code changes began.

MAIN DESIGN AREAS
- Worker command/result protocol and protocol versioning.
- Scanner identity ownership across the process boundary.
- App↔worker cancellation semantics.
- Worker restart behaviour without job retry/resumption.
- Worker-local concurrency without introducing a queue.
- Resource ceilings to be measured rather than guessed.
- Compose/network separation.
- Host-level egress-hardening acceptance criteria.
- Documentation changes required after the design is actually proven.

IMPORTANT: THIS VERSION WAS LATER CORRECTED
Step 0.1 contained several assumptions that Step 0.2 explicitly corrected. The evidence value
of this step is therefore not "the design was perfect"; it is that the design was reviewed
critically before implementation and corrected when repository evidence contradicted it.

CORRECTIONS LATER IDENTIFIED
- Host capacity had been read from stale prose instead of the current measured Compose record.
- A proposed production identity fallback would have violated the existing fail-closed invariant.
- Restart reasoning incorrectly implied a restarted worker could retry in-flight work.
- The proposed egress deny list was only a sample and did not match the full address-policy contract.

WHY THIS MATTERS FOR THE PERSONAL PROJECT
This is useful reflection evidence: the project changed direction because review found
specific flaws. The strongest PP use is to explain one correction, what evidence exposed it,
and how the design improved as a result.

USEFUL ATL CONNECTIONS
