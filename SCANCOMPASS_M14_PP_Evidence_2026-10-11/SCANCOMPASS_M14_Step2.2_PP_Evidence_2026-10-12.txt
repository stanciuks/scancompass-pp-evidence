3. THE FOUR PRIMITIVES, AND THE CONFIDENTIALITY BOUNDARY
   (SOURCE-RECORDED) [S2]

Each is described by PURPOSE ONLY. No check identifier, header name, record
name, directive name or source path is reproduced in this note.

  HTML DOCUMENT FACTS. Parses a document and reports what it saw: the frozen
  base in effect, scripts and their integrity metadata, active subresource
  references counted BY KIND, forms and their submission targets and
  ownership, and any policy delivered by markup rather than by a header. It
  reports COMPLETENESS as a first-class fact, not as an afterthought.
  FORM-POINTER PARSING. A second entry point that runs the parser while
  recording, at the moment each element is created, which form the parser
  itself considered that element to belong to. Section 7 is why this exists.
  POLICY HEADER FACTS. Reads the security policy a server sent as headers and
  reports the dispositions SEPARATELY AND WITHOUT EVER MERGING THEM, with
  per-disposition counts and the presence or absence of the two directives that
  bear on insecure subresources, plus a bound-reached flag.
  REGISTRY AND MAIL-REPORTING FACTS. Reads the registry response's signing
  declaration as an OWN MEMBER ONLY, NEVER COERCING A TYPE, and reads the mail
  policy record's two reporting tags under explicit bounds.

THE CONFIDENTIALITY BOUNDARY IS THE STRICTEST PART OF THE DESIGN, AND IT IS
TESTED, NOT ASSERTED. Every reference is resolved and then REDUCED TO A SCHEME
TOKEN AND A HOSTNAME. The record states that NO PATH, QUERY, FRAGMENT, FIELD

TOKEN OR A HOSTNAME, and that no path, query, fragment, field name, field

7. FORM OWNERSHIP: WHAT A BROWSER ACTUALLY DOES, AND THE LIMITS OF PROVING IT
   [S2]

WHY IT MATTERS. Whether a password field belongs to a form with an insecure
target is the difference between a serious finding and nothing at all. A
TREE WALK GETS THIS WRONG ON REAL LEGACY PAGES, because the HTML standard
associates a control with the form the PARSER had open when the control was
created — which, on mis-nested markup, is NOT its ancestor in the resulting
tree.

THE FIRST REVIEW ROUND FOUND EXACTLY THIS. Two layouts were named: a form
inside a table, and a form closed by a stray tag mid-structure. On both, a
purely structural reading MISSES THE ASSOCIATION a browser would make.

THE FIX READS THE PARSER'S OWN ASSOCIATION AT THE MOMENT OF ELEMENT CREATION,
which is where the standard's association step sits. The precedence is: an
explicit owner attribute, resolved with the standard's own
first-element-with-that-identifier rule AND REQUIRING THAT ELEMENT TO BE A
FORM; then the parser's pointer; then the nearest ancestor. NO OWNERSHIP IS
EVER INFERRED FROM AN UNRELATED PASSWORD FIELD. [S2]

IT FAILS CLOSED. The hook reads members of the exactly pinned parser library
that are documented as internal. A RUNTIME SHAPE CHECK MEANS THAT IF THE
LIBRARY STOPS EXPOSING THEM, EXTRACTION RETURNS "NOT PARSED" RATHER THAN A
WRONG ANSWER, and that path is tested by mocking a pointer-less parser. [S2]

HOW BROWSER EQUIVALENCE WAS TESTED, AND EXACTLY WHAT THAT DOES AND DOES NOT
ESTABLISH. The tree the recording parser produces is ASSERTED IDENTICAL TO THE
LIBRARY'S ORDINARY PARSE ACROSS NINE DOCUMENTS, by serialisation. A dedicated
49-test file covers both review layouts, the clearing of the pointer, pointer-
associated overrides, a mis-nested second form, inert template content, two
unrelated-password cases and four owner-attribute cases including duplicate
identifiers.

THE SCOPE LIMITATION IS STATED PLAINLY AND MUST NOT BE OVERSTATED: THIS IS
EQUIVALENCE TO ONE PARSER LIBRARY'S IMPLEMENTATION OF THE STANDARD, NOT TO ANY
SHIPPING BROWSER. NO BROWSER WAS RUN. The record goes further and names a
divergence it knows about: the library implements the standard's control model
for selection elements, not a current browser engine's newer model, so facts
about controls placed inside a selection element CAN DIFFER FROM THAT BROWSER.
It also records that the specification hosts WERE UNREACHABLE from the
container during the correction rounds, so NO SPECIFICATION TEXT WAS RE-READ
and the standards statements are the author's knowledge, NOT INDEPENDENTLY
VERIFIED. ONE OPEN OWNER DECISION IS LEFT OPEN FOR PRECISELY THAT REASON. [S2]

A CORRECTION THAT WENT AGAINST THE PROJECT'S INTEREST IS RECORDED AS SUCH. The
first reading treated a form whose buttons all override an insecure target as
safe. The review corrected it: A SCRIPT CAN SUBMIT THE FORM DIRECTLY AND REACH
THE FORM'S OWN INSECURE TARGET WHATEVER THE BUTTONS SAY. The primitive's

8. POLICY, REGISTRY AND MAIL FACTS: THE CONSERVATIVE DIRECTION, CHOSEN
   DELIBERATELY (SOURCE-RECORDED) [S2]

  MULTIPLE POLICIES IN ONE HEADER FIELD ARE READ AS MULTIPLE POLICIES. The
  primitive splits a header field into a policy list on separators outside
  quotes and follows the standard's parse rule for each. THIS IS THE SINGLE
  BEHAVIOUR THE EXISTING FREE CODE GETS WRONG, and section 10 records that as
  a measured finding left unfixed.
  THE TWO DISPOSITIONS ARE KEPT APART AND NEVER MERGED. Enforced and
  report-only are separate structures with separate counts. A report-only
  policy must never be credited as protection, and the type system makes
  merging them impossible rather than merely discouraged.
  A DIRECTIVE THAT TAKES NO VALUE BUT CARRIES ONE IS RECORDED AS PRESENT-WITH-
  A-VALUE AND IS NOT CREDITED AS PRESENT. The recorded reason is the right
  one: CREDITING A MALFORMED DIRECTIVE COULD ONLY SOFTEN A DOWNSTREAM FINDING.
  Whether a browser honours such a directive COULD NOT BE VERIFIED and IS NOT
  ASSERTED EITHER WAY; it is one of the five open owner decisions.
  POLICY DELIVERED BY MARKUP IS RECORDED AND NEVER APPLIED. The facts include
  how many such policies there are, how many are in the document head, and how
  many active references occur BEFORE the first one — because a policy
  delivered partway down a document CANNOT REACH WHAT THE BROWSER ALREADY
  FETCHED. Whether it may soften a finding is an OPEN OWNER DECISION, and the
  primitive takes neither side.
  THE REGISTRY'S SIGNING DECLARATION IS READ AS AN OWN MEMBER ONLY, AND TYPES
  ARE NEVER COERCED: a string that merely looks like a boolean is MALFORMED,
  not true. A declaration of "not signed" accompanied by signing data —
  WELL-FORMED OR MALFORMED — is CONTRADICTORY, because data that might be
  signing data is never read as "none". NO KEY MATERIAL, DIGEST, TAG OR
  ALGORITHM IS RETAINED, and a fact recording that the result is NOT
  INDEPENDENTLY VALIDATED travels with every value.
  THE MAIL REPORTING TAGS ARE BOUNDED AT EVERY LEVEL and the output CARRIES NO
  DESTINATION. Tag names are matched case-insensitively IDENTICALLY TO THE
  EXISTING FREE PARSER, so the two CANNOT DISAGREE ABOUT WHICH TAG EXISTS — an
  internal-consistency property chosen on purpose. A REPEATED TAG IS RECORDED
  AS DUPLICATE AND NO OCCURRENCE IS CHOSEN.

EVERY LIST AND HOST SET IS BOUNDED, AND EVERY BOUND SETS AN EXPLICIT FLAG. The
rule the record gives is the one that matters: A BOUND MUST NEVER SILENTLY
BECOME AN ABSENCE. Totals stay exact even where retained detail is capped. A
review round found that THREE HOST SETS AND ONE PER-FORM OVERRIDE LIST HAD NO
SUCH FLAG, and all four were added. A later round added the same treatment to
a markup-delivered policy hitting its directive cap. [S2]
