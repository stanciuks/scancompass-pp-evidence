8. THE DOMAINS LINK, AND WHY IT IS NOT IN THE HEADER

Until this point the domain page was reachable only by typing its address. The
owner asked for a link. The recorded decision is that it goes in the SIGNED-IN
STATE OF THE ACCOUNT PANEL, not in the site header:

  - the header is server-rendered and knows nothing about the visitor. A header
    link would show an account-only destination to EVERYONE, signed out
    included;
  - the account panel learns that the visitor is signed in from an existing
    session request after hydration. A link rendered there is only ever in
    client output, and only for a signed-in visitor.

It is NAVIGATION ONLY. No API route, no domain logic, no gate behaviour and no
server code changed, and rendering the link makes no request beyond the session
request that already happened. The domain page still decides for itself: with
the gate closed every domain route answers 404 and the page shows its existing
unavailable notice; signed out, it asks the visitor to sign in.

Five new tests pin that there is exactly one such link, with exactly the right
address, only when signed in; that it is ABSENT while loading, when signed out,
and when the feature is unavailable; and that it is ABSENT FROM THE SERVER-
RENDERED MARKUP of both the panel and the account page. Two mutations — a
wrong address, and a link added to the signed-out state — each fail. [S3]
