FAILURES / CHANGES DURING REVIEW
1. Initial persistence array handling broke browser/storage admissibility symmetry
   in both directions:
   - ["x".repeat(300)] survived browser output but disappeared from storage.
   - [""] was rejected by the browser but retained by persistence.
   The fix made both projections use the same renderEvidenceValue() admissibility
   decision.

2. Structured array retention was revised so the final string element may be
   truncated to the remaining 200-character textual budget, matching the
   browser's existing cap while preserving structured array form.

3. A first test expectation incorrectly assumed ["", ""] should be dropped.
   Existing browser behavior renders it as ", ", so the test was corrected to
   reflect actual behavior instead of changing production semantics to satisfy
   an invented expectation.

4. An early boundary-test design intentionally failed as soon as
   src/server/persistence/** appeared. That would have broken Step 4 before the
   Step 7 finding writer existed. The trap was removed. The concrete assertion
   that the writer must call persistableEvidence() is now a Step 7 obligation.

5. Removing that trap temporarily left an unbalanced brace in
   tests/boundaries.test.ts. Full gates caught it and it was repaired before
   commit.

6. The golden-report maintenance comment was softened so Step 3 requires byte
   identity but future deliberate report changes can update the golden only with
   explicit review and documentation.

7. EXPOSURE.SECURITY_TXT was initially described as having 10 allowlisted keys.
   Inspection showed 9 allowlisted keys; its widest current runtime branch
   retains exactly 8, leaving zero headroom under the shared cap. This is now
   pinned by test.

8. docs/DATA_MODEL.md still said functional implementation had not started after
   real Step 3 source code existed. Its banner was corrected to describe the
   schema specifically: approved but not implemented.

9. No production state changed during Step 3.
