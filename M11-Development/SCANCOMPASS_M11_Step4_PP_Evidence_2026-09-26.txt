- public schema is not used for SCANCOMPASS objects

BIGSERIAL PRIVILEGE FINDING
`scan_findings.id` remains BIGSERIAL.
The review found that table INSERT is not enough when the default calls nextval().
The app role therefore receives exactly:
GRANT USAGE ON SEQUENCE scancompass.scan_findings_id_seq

LEAST-PRIVILEGE APPLICATION ROLE
- scans: SELECT / INSERT / UPDATE / DELETE
- scan_findings: INSERT only
- scan_reports: SELECT / INSERT only
- report_management_tokens: SELECT / INSERT / UPDATE
- report_shares: SELECT / INSERT / UPDATE
- report_deliveries: SELECT / INSERT / UPDATE
- schema_migrations: no app privileges
- scan_findings_id_seq: USAGE only

COPY WORDING CORRECTION
The earlier design phrase "no COPY" was removed because PostgreSQL does not have a
separate client COPY privilege beyond underlying SELECT/INSERT rights.
The security control is instead:
- not superuser
- no pg_read_server_files
- no pg_write_server_files
- no pg_execute_server_program

MIGRATION DESIGN
Initial migration:
db/migrations/0000_m11_persistence.sql

Drizzle Kit 0.31.11 naturally numbers the first indexed migration 0000. The repo
follows the tool rather than renaming the SQL or editing its journal.

Runner characteristics:
- explicit operator invocation only
- never migration-on-boot
- exact migration bytes SHA-256 checked
- transaction-scoped advisory lock
- dedicated schema must already exist
- first run requires an otherwise-empty application schema
- initial migration creates all seven tables, including schema_migrations
- ledger row written in the same transaction
- checksum mismatch refuses
- unexpected pre-existing objects refuse
- malformed/missing ledger state refuses
- unknown applied migration versions refuse
- no automatic repair of migration history

DESTRUCTIVE INTEGRATION SAFETY
The original hostname-substring guard was replaced with positive scratch-target
identification:
- PERSISTENCE_IT_DATABASE_URL required
- PERSISTENCE_IT_ADMIN_DATABASE_URL required
- both identify the same database
- database name must match `scancompass_it_<suffix>`
- PERSISTENCE_IT_ALLOW_DESTRUCTIVE=1 required
- target must not collide with DATABASE_URL or DATABASE_MIGRATION_URL
- present-but-unparseable protected URLs cause refusal
- refusal details do not expose credentials

BOUNDARY HARDENING DISCOVERIES
1. ESLint flat-config overlap had caused one no-restricted-imports rule to replace
   another for scanner files. The config was corrected.
2. `assertServerOnly` in ledger.ts had accidentally been placed inside a docblock.
3. The old boundary test only searched raw text, so a commented-out guard could
   satisfy it. The test now strips comments, requires a real import, and requires
   an active guard call; three mutation cases were tested.

UNKNOWN APPLIED MIGRATION FIX
The first runner version ignored ledger rows for migrations missing from the local
checkout. Step 4 added UNKNOWN_APPLIED_MIGRATION so an old migration runner refuses
to manage a newer migration history.
