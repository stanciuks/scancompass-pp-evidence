PURPOSE
Define the exact bytes of a future stored public report and a pure verification
path that converts stored bytes back into a trusted PublicAssessmentReport or
refuses them, before any database writer exists.

DOCUMENT VERSION
Current version:
public-report-v1

Rules:
- one source literal
- no trimming
- no case folding
- no aliases
- no prefix matching
- no fallback to current

After the follow-up fix, SUPPORTED_DOCUMENT_VERSIONS is the source of the closed
ReportDocumentVersion union.

The verifier now explicitly dispatches by document version:
- public-report-v1 -> v1 verifier
- unsupported string -> UNSUPPORTED_DOCUMENT_VERSION
- future supported version with no loader -> compile-time failure

SERIALIZATION CONTRACT
Issuance:
1. strict v1 runtime schema validates the source report
2. JSON.stringify(report) exactly once
3. Buffer.from(document, "utf8") exactly once
4. byte size taken from those exact UTF-8 bytes
5. enforce issuance-size limit
6. SHA-256 over those exact bytes
7. return issued artifact

No:
- key sorting
- canonical-JSON library
- replacer
- pretty printing
- parse/re-stringify
- serialization of Zod validation.data

The format is deliberately not canonical JSON. Reproducibility comes from the
deterministic PublicAssessmentReport producer.

ISSUED ARTIFACT
- document: string
- documentVersion: closed ReportDocumentVersion
- byteSize: UTF-8 bytes
- sha256: raw 32-byte Buffer

STORED / UNTRUSTED INPUT
- document: string
- documentVersion: string
- byteSize: number
- sha256: Buffer of any length

VERSION-DISPATCH FOLLOW-UP DEFECT
The first Step 6 implementation checked whether a stored version appeared in
SUPPORTED_DOCUMENT_VERSIONS but then always validated with the v1 schema.

Because ReportDocumentVersion was independently declared as v1, a future v2
could have been added to the supported tuple without widening the exhaustive
type. Such a document could pass the supported-version guard and fall through to
the v1 validator.

FOLLOW-UP FIX
- supported tuple now defines the version union
- verifier now switches explicitly on the narrowed version
- v1 verification lives in the v1 branch
- exhaustive default calls assertNever

Compile-time mutation:
adding public-report-v2 to the supported tuple without adding a loader produced:

TS2345:
Argument of type '"public-report-v2"' is not assignable to parameter of type
'never'.

After restoration, typecheck passed again.
