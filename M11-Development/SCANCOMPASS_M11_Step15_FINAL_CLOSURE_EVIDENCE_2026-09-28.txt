9. DEPLOYMENT INCIDENTS

-----------------------

Two deployment defects occurred. Both are recorded because the rollback and

source-fix paths working is part of the evidence the gates were real.


INCIDENT 1 - application image stage

  - the Compose build block for the app service specified no target, so it built

    the Dockerfile's LAST stage (acceptance) instead of runtime;

  - the production container restart-looped;

  - recovered;

  - fixed IN SOURCE with an explicit \target: runtime\;

  - a structural test was added so the omission cannot recur silently.


INCIDENT 2 - share-shell redirect loop

  - installing step 14's edge produced an infinite redirect loop:

      GET /r   -> nginx 301 Location: /r/

      GET /r/  -> Next  308 Location: /r

  - cause: nginx answers a slashless URI with a 301 to the slash form when the

    matching prefix location ends in '/' and is handled by proxy_pass, while Next

    canonicalises in the opposite direction;

  - nginx -t had passed and the reload had succeeded; EXTERNAL ACCEPTANCE caught it,

    failing with: curl: (47) Maximum (50) redirects followed;

  - the ROLLBACK SUCCEEDED and restored the previous files;

  - PR #11 fixed it in source by adding the exact \location = /r\ alongside the

    \^~ /r/\ prefix (the documented nginx remedy), reproduced on nginx 1.24.0 before

    merging;

  - the corrected edge was deployed, is byte-identical to the committed source,

    passes nginx -t, and survived the controlled reboot.
