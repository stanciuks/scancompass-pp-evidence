FAILURES / CHANGES DURING REVIEW
1. Initial collection-script wording incorrectly implied nginx -t did not read the
   secret include. In reality nginx -t parses the active include graph internally.
   The guarantee was rewritten precisely: no secret content is directly collected
   or printed.

2. The first nginx -t filter could have leaked an entire raw error line if that line
   contained both a secret and the phrase "test failed".
   It was redesigned so raw nginx -t text never reaches stdout; only locally-authored
   yes/no/integer summaries are emitted.

3. A content-safety gate was added before either live config file could be printed.
   If either approved file failed the gate, neither full file would be emitted.

4. hash_file initially allowed a failed sha256sum pipeline to appear as a blank
   successful hash because awk supplied the pipeline exit status.
   This was detected during end-to-end testing and corrected.

5. The live installed template had misleading comments after hostname substitution,
   including wording equivalent to "scancompass.com cannot resolve".
   Repository comments were rewritten to describe "the placeholder" generically,
   without changing active behavior.

6. The first new test incorrectly treated the existing SCANCOMPASS_TLS shared-memory
   zone label as a hostname occurrence.
   The test was narrowed to scancompass.com and the zone label was deliberately
   preserved.

7. The initial security.txt MIME explanation overstated what would happen without
   types { }.
   It was corrected to state only that types { } clears inherited
   extension-to-MIME mappings so the explicit default_type is authoritative.

8. No production state changed during Step 2.
